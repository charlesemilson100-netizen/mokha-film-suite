# Requirements Document

## Introduction

The Story Blueprint Engine transforms MOKHA FILM Suite's Story Engine from a prompt-writing tool into a professional scriptwriting platform for Hollywood writers, marketing teams, and content creators. It combines a 7-step configuration wizard that generates a structured Story Blueprint with a Final Draft-style Pro Script Builder where writers compose fully formatted scripts. The system supports three writing modes (user-written primary, template-generated secondary, AI-generated tertiary) and integrates seamlessly with existing Director Brain, Shot Critique, and Agentic Mode features.

## Glossary

- **Story_Blueprint**: A structured JSON configuration object generated by the 7-step wizard that encodes all story parameters (type, duration, style, narrative structure, intent, characters) and drives the Pro Script Builder UI and behavior.
- **Pro_Script_Builder**: The Final Draft-style scriptwriting interface where writers compose fully formatted scripts with scene headings, action lines, dialogue blocks, and parentheticals as editable fields.
- **Configuration_Wizard**: A 7-step guided interface that collects story parameters and generates the Story Blueprint.
- **Story_Type**: The category of story being written (Social Media, Short Film, Cinematic Film, Documentary, Commercial, Experimental).
- **Duration_Bracket**: A predefined duration range (2 min, 5 min, 10 min, 15 min, 30 min, 60 min) selected in the wizard.
- **Style**: The visual and tonal aesthetic of the story (cinematic, documentary, comedy, drama, 3D anime, 2D animated, etc.).
- **Narrative_Structure**: The story framework (protagonist journey, antagonist conflict, ensemble, real event storytelling, etc.).
- **Dynamic_Parameters**: Context-dependent configuration options that change based on previous wizard selections.
- **Story_Intent**: The primary emotional, thematic, or audience goal of the story.
- **Character_Arc**: The transformation or journey of a character from beginning to end, including key turning points and emotional beats.
- **Character_Relationship**: The defined connection between two characters (protagonist/antagonist, mentor/student, love interest, etc.).
- **Scene_Heading**: A line indicating location and time of day (e.g., "INT. COFFEE SHOP - DAY").
- **Action_Line**: Narrative description of what happens on screen.
- **Dialogue_Block**: Character name, parenthetical, and spoken words.
- **Parenthetical**: Actor direction within dialogue (e.g., "(beat)", "(whispers)").
- **Writing_Mode**: The approach to script composition (user-written, template-generated, AI-generated).
- **Script_Template**: A pre-structured script scaffold with placeholder scene headings, action lines, and dialogue blocks based on story type and structure.
- **Export_Format**: The file format for script export (PDF, TXT).
- **Prompt_Conversion**: The optional process of converting a completed script into shot-by-shot prompts for the Director Brain.
- **Pro_Mode**: The professional scriptwriting entry point, distinct from the existing Story Engine prompt-writing mode.
- **Director_Brain**: The existing AI director chat panel that can analyze scripts and provide cinematic feedback.
- **Shot_Critique**: The existing feature for analyzing individual shots.
- **Agentic_Mode**: The existing Director Brain upgrade with propose-and-confirm action execution.

## Requirements

### Requirement 1: 7-Step Configuration Wizard - Story Type Selection

**User Story:** As a screenwriter, I want to select the type of story I'm writing in the first step, so that the wizard can tailor all subsequent options to my project's format and scope.

#### Acceptance Criteria

1. WHEN the user opens Pro Mode, THE Configuration_Wizard SHALL display Step 1 with a list of Story_Type options: Social Media, Short Film, Cinematic Film, Documentary, Commercial, Experimental.
2. WHEN the user selects a Story_Type, THE Configuration_Wizard SHALL store the selection in the Story_Blueprint and enable the Next button to proceed to Step 2.
3. IF the user has not selected a Story_Type, THEN THE Next button SHALL remain disabled.
4. WHEN the user selects a Story_Type, THE Configuration_Wizard SHALL display a one-line description of that type (e.g., "Social Media: 15-60 second vertical video for platforms like TikTok, Instagram Reels, YouTube Shorts").
5. WHEN the user clicks Back from Step 2 or later, THE Configuration_Wizard SHALL return to Step 1 with the previously selected Story_Type pre-selected.
6. THE Configuration_Wizard SHALL NOT proceed to Step 2 until a Story_Type is selected.

### Requirement 2: 7-Step Configuration Wizard - Duration Selection

**User Story:** As a screenwriter, I want to select the target duration for my story in Step 2, so that the wizard can recommend appropriate narrative structures and scene counts.

#### Acceptance Criteria

1. WHEN the user completes Step 1 and clicks Next, THE Configuration_Wizard SHALL display Step 2 with predefined Duration_Bracket options: 2 min, 5 min, 10 min, 15 min, 30 min, 60 min.
2. WHEN the user selects a Duration_Bracket, THE Configuration_Wizard SHALL store the selection in the Story_Blueprint and enable the Next button.
3. WHEN the user selects a Duration_Bracket, THE Configuration_Wizard SHALL display the typical scene count range for that duration (e.g., "5 min: typically 3-5 scenes").
4. IF the user has not selected a Duration_Bracket, THEN THE Next button SHALL remain disabled.
5. WHEN the user clicks Back from Step 3 or later, THE Configuration_Wizard SHALL return to Step 2 with the previously selected Duration_Bracket pre-selected.
6. THE Configuration_Wizard SHALL NOT proceed to Step 3 until a Duration_Bracket is selected.

### Requirement 3: 7-Step Configuration Wizard - Style Selection

**User Story:** As a screenwriter, I want to select the visual and tonal style of my story in Step 3, so that the Pro Script Builder can recommend appropriate formatting and the Director Brain can provide style-specific feedback.

#### Acceptance Criteria

1. WHEN the user completes Step 2 and clicks Next, THE Configuration_Wizard SHALL display Step 3 with Style options including: cinematic, documentary, comedy, drama, 3D anime, 2D animated, and others.
2. WHEN the user selects a Style, THE Configuration_Wizard SHALL store the selection in the Story_Blueprint and enable the Next button.
3. WHEN the user selects a Style, THE Configuration_Wizard SHALL display a brief description of that style's visual and tonal characteristics.
4. IF the user has not selected a Style, THEN THE Next button SHALL remain disabled.
5. WHEN the user clicks Back from Step 4 or later, THE Configuration_Wizard SHALL return to Step 3 with the previously selected Style pre-selected.
6. THE Configuration_Wizard SHALL NOT proceed to Step 4 until a Style is selected.

### Requirement 4: 7-Step Configuration Wizard - Narrative Structure Selection

**User Story:** As a screenwriter, I want to select the narrative framework for my story in Step 4, so that the Pro Script Builder can generate an appropriate scene structure and the Director Brain can provide structure-specific analysis.

#### Acceptance Criteria

1. WHEN the user completes Step 3 and clicks Next, THE Configuration_Wizard SHALL display Step 4 with Narrative_Structure options including: protagonist journey, antagonist conflict, ensemble, real event storytelling, and others.
2. WHEN the user selects a Narrative_Structure, THE Configuration_Wizard SHALL store the selection in the Story_Blueprint and enable the Next button.
3. WHEN the user selects a Narrative_Structure, THE Configuration_Wizard SHALL display a description of that structure's key story beats and character roles.
4. IF the user has not selected a Narrative_Structure, THEN THE Next button SHALL remain disabled.
5. WHEN the user clicks Back from Step 5 or later, THE Configuration_Wizard SHALL return to Step 4 with the previously selected Narrative_Structure pre-selected.
6. THE Configuration_Wizard SHALL NOT proceed to Step 5 until a Narrative_Structure is selected.

### Requirement 5: 7-Step Configuration Wizard - Dynamic Parameters

**User Story:** As a screenwriter, I want Step 5 to present context-dependent options based on my previous selections, so that I only see relevant parameters for my specific story type and structure.

#### Acceptance Criteria

1. WHEN the user completes Step 4 and clicks Next, THE Configuration_Wizard SHALL display Step 5 with Dynamic_Parameters that vary based on the Story_Type, Duration_Bracket, Style, and Narrative_Structure selected in previous steps.
2. WHEN the Story_Type is "Documentary", THE Configuration_Wizard SHALL display Dynamic_Parameters for: subject matter, interview format, archival footage availability, and narrator presence.
3. WHEN the Story_Type is "Commercial", THE Configuration_Wizard SHALL display Dynamic_Parameters for: product category, target audience, call-to-action type, and brand tone.
4. WHEN the Story_Type is "Cinematic Film", THE Configuration_Wizard SHALL display Dynamic_Parameters for: genre, protagonist archetype, antagonist type, and act structure preference (three-act, five-act, or sequence-based).
5. WHEN the user selects Dynamic_Parameters, THE Configuration_Wizard SHALL store all selections in the Story_Blueprint and enable the Next button.
6. IF the user has not completed all required Dynamic_Parameters, THEN THE Next button SHALL remain disabled.
7. WHEN the user clicks Back from Step 6 or later, THE Configuration_Wizard SHALL return to Step 5 with all previously selected Dynamic_Parameters pre-selected.

### Requirement 6: 7-Step Configuration Wizard - Story Intent

**User Story:** As a screenwriter, I want to define the emotional, thematic, or audience goal of my story in Step 6, so that the Director Brain can provide intent-aligned feedback and the Pro Script Builder can suggest appropriate tone and pacing.

#### Acceptance Criteria

1. WHEN the user completes Step 5 and clicks Next, THE Configuration_Wizard SHALL display Step 6 with a text input field for Story_Intent.
2. THE Configuration_Wizard SHALL display example Story_Intent statements (e.g., "Make the audience feel hopeful about climate change", "Convince viewers to try our new product", "Explore the tension between ambition and family").
3. WHEN the user enters a Story_Intent, THE Configuration_Wizard SHALL store it in the Story_Blueprint and enable the Next button.
4. IF the user has not entered a Story_Intent, THEN THE Next button SHALL remain disabled.
5. WHEN the user clicks Back from Step 7, THE Configuration_Wizard SHALL return to Step 6 with the previously entered Story_Intent pre-filled.
6. THE Configuration_Wizard SHALL NOT proceed to Step 7 until a Story_Intent is entered.

### Requirement 7: 7-Step Configuration Wizard - Character Creation & Relationships

**User Story:** As a screenwriter, I want to optionally define characters and their relationships in Step 7, so that the Pro Script Builder can suggest character-appropriate dialogue and the Director Brain can analyze character presence and arcs.

#### Acceptance Criteria

1. WHEN the user completes Step 6 and clicks Next, THE Configuration_Wizard SHALL display Step 7 with an optional Character_Creation interface.
2. THE Configuration_Wizard SHALL display a message: "Character creation is optional — you can skip this step and add characters directly in the Pro Script Builder."
3. WHEN the user clicks "Add Character", THE Configuration_Wizard SHALL display a form with fields: character name, archetype, age, role (protagonist, antagonist, mentor, love interest, etc.), and a brief description.
4. WHEN the user adds a character, THE Configuration_Wizard SHALL store the character in the Story_Blueprint.
5. WHEN the user adds multiple characters, THE Configuration_Wizard SHALL display a "Define Relationships" interface where the user can specify the relationship between any two characters (e.g., "Alice is the mentor of Bob").
6. WHEN the user clicks "Skip Character Creation", THE Configuration_Wizard SHALL proceed to the Pro Script Builder with an empty character list, allowing the user to add characters later.
7. WHEN the user completes Step 7 (either by adding characters or skipping), THE Configuration_Wizard SHALL generate the Story_Blueprint and open the Pro Script Builder.
8. THE Configuration_Wizard SHALL NOT force character creation — users must be able to proceed to the Pro Script Builder without defining any characters.

### Requirement 8: Story Blueprint JSON Architecture

**User Story:** As a developer, I want the Story Blueprint to be a modular, extensible JSON structure, so that new story types, styles, and parameters can be added without redesigning the system.

#### Acceptance Criteria

1. THE Story_Blueprint SHALL be a JSON object with the following top-level structure:
   `json
   {
     "id": "unique-blueprint-id",
     "storyType": "string",
     "duration": "string",
     "style": "string",
     "narrativeStructure": "string",
     "dynamicParameters": {},
     "storyIntent": "string",
     "characters": [],
     "relationships": [],
     "createdAt": "ISO-8601 timestamp",
     "updatedAt": "ISO-8601 timestamp"
   }
   `
2. THE Story_Blueprint.dynamicParameters field SHALL be a flexible object that stores context-dependent parameters as key-value pairs, allowing different parameter sets for different story types without schema changes.
3. THE Story_Blueprint.characters field SHALL be an array of character objects, each with: id, name, archetype, age, role, description, and an optional arc field for character arc data.
4. THE Story_Blueprint.relationships field SHALL be an array of relationship objects, each with: characterId1, characterId2, relationshipType, and description.
5. WHEN a new Story_Type is added to the system, THE Story_Blueprint schema SHALL NOT require modification — only the Configuration_Wizard logic and Pro Script Builder templates need to be updated.
6. WHEN the Pro Script Builder is opened, THE Pro Script Builder SHALL load the Story_Blueprint and use it to configure the UI, scene structure, and character suggestions.
7. THE Story_Blueprint SHALL be persisted to the project state and remain accessible throughout the user's session.

### Requirement 9: Pro Script Builder - Final Draft-Style Interface

**User Story:** As a screenwriter, I want the Pro Script Builder to provide a Final Draft-style editing interface, so that I can write fully formatted scripts with proper screenplay conventions without manual formatting.

#### Acceptance Criteria

1. WHEN the Pro Script Builder opens, THE Pro Script Builder SHALL display a blank script with a structure based on the Story_Blueprint's Narrative_Structure and Duration_Bracket.
2. THE Pro Script Builder SHALL display editable fields for: Scene_Heading, Action_Line, Dialogue_Block (with character name, parenthetical, and dialogue), and Parenthetical.
3. WHEN the user types a Scene_Heading (e.g., "INT. COFFEE SHOP - DAY"), THE Pro Script Builder SHALL automatically format it in all caps and apply proper screenplay styling.
4. WHEN the user types an Action_Line, THE Pro Script Builder SHALL apply proper screenplay formatting (left-aligned, single-spaced).
5. WHEN the user types a Dialogue_Block, THE Pro Script Builder SHALL automatically format the character name in all caps, center the parenthetical, and left-align the dialogue.
6. WHEN the user presses Tab or Enter in a field, THE Pro Script Builder SHALL move to the next appropriate field (e.g., from Scene_Heading to Action_Line, from Dialogue to Parenthetical).
7. THE Pro Script Builder SHALL display a live page count and estimated runtime based on the script content.
8. THE Pro Script Builder SHALL support keyboard shortcuts for common screenplay elements (e.g., Ctrl+H for Scene_Heading, Ctrl+A for Action_Line, Ctrl+D for Dialogue).

### Requirement 10: Pro Script Builder - Structure Adaptation

**User Story:** As a screenwriter, I want the Pro Script Builder to adapt its scene structure based on my story's narrative framework, so that the script structure matches my chosen story type and duration.

#### Acceptance Criteria

1. WHEN the Pro Script Builder opens with a Story_Blueprint containing a Narrative_Structure of "protagonist journey", THE Pro Script Builder SHALL generate a scene structure with: Inciting Incident, Rising Action, Midpoint, Climax, and Resolution.
2. WHEN the Pro Script Builder opens with a Story_Blueprint containing a Narrative_Structure of "antagonist conflict", THE Pro Script Builder SHALL generate a scene structure with: Antagonist Introduction, Conflict Escalation, Confrontation, and Resolution.
3. WHEN the Pro Script Builder opens with a Story_Blueprint containing a Narrative_Structure of "ensemble", THE Pro Script Builder SHALL generate a scene structure with multiple parallel storylines and intersection points.
4. WHEN the Pro Script Builder opens with a Story_Blueprint containing a Duration_Bracket of "5 min", THE Pro Script Builder SHALL generate a structure with 3-5 scenes.
5. WHEN the Pro Script Builder opens with a Story_Blueprint containing a Duration_Bracket of "30 min", THE Pro Script Builder SHALL generate a structure with 8-12 scenes.
6. WHEN the user adds a new scene, THE Pro Script Builder SHALL insert it at the user's chosen position and update all subsequent scene numbers.
7. THE Pro Script Builder SHALL NOT use a fixed act structure — the structure SHALL adapt based on the Story_Blueprint's Narrative_Structure and Duration_Bracket.

### Requirement 11: Three Writing Modes - User-Written Primary

**User Story:** As a screenwriter, I want the Pro Script Builder to provide a blank, structured script where I write all content, so that I maintain full creative control and the tool acts as a formatting assistant rather than a content generator.

#### Acceptance Criteria

1. WHEN the Pro Script Builder opens, THE default Writing_Mode SHALL be "user-written".
2. IN user-written mode, THE Pro Script Builder SHALL display a blank script structure with empty editable fields for Scene_Heading, Action_Line, Dialogue_Block, and Parenthetical.
3. IN user-written mode, THE Pro Script Builder SHALL NOT auto-generate any script content — all content SHALL be entered by the user.
4. IN user-written mode, THE Pro Script Builder SHALL provide real-time formatting assistance (auto-capitalization, field navigation, page count).
5. IN user-written mode, THE Pro Script Builder SHALL allow the user to add, delete, and reorder scenes freely.
6. WHEN the user switches to a different Writing_Mode, THE Pro Script Builder SHALL preserve all user-written content.
7. THE user-written mode SHALL be the primary, default Writing_Mode — users should not need to explicitly select it.

### Requirement 12: Three Writing Modes - Template-Generated Secondary

**User Story:** As a screenwriter, I want the Pro Script Builder to optionally generate a script scaffold based on story templates, so that I can use it as a starting point and then customize it with my own content.

#### Acceptance Criteria

1. WHEN the user clicks "Generate from Template" in the Pro Script Builder, THE Pro Script Builder SHALL display a list of Script_Templates matching the Story_Blueprint's Story_Type, Narrative_Structure, and Duration_Bracket.
2. WHEN the user selects a Script_Template, THE Pro Script Builder SHALL populate the script with placeholder Scene_Heading, Action_Line, Dialogue_Block, and Parenthetical entries based on the template.
3. THE Script_Template placeholders SHALL be clearly marked (e.g., "[SCENE HEADING]", "[ACTION]", "[CHARACTER NAME]") so the user can easily identify what needs to be customized.
4. WHEN the user edits a placeholder, THE placeholder marker SHALL be replaced with the user's content.
5. WHEN the user generates from a template, THE Pro Script Builder SHALL preserve the template structure but allow the user to add, delete, and reorder scenes.
6. THE template-generated mode SHALL be optional — users must explicitly choose to generate from a template.
7. WHEN the user generates from a template, THE Pro Script Builder SHALL display a message: "This is a template scaffold. Customize it with your own content."

### Requirement 13: Three Writing Modes - AI-Generated Tertiary

**User Story:** As a screenwriter, I want the Pro Script Builder to optionally generate a full script draft using AI, so that I can use it as a creative starting point and then refine it.

#### Acceptance Criteria

1. WHEN the user clicks "Generate with AI" in the Pro Script Builder, THE Pro Script Builder SHALL display a confirmation dialog: "This will generate a full script draft using AI. You can edit it afterward."
2. WHEN the user confirms, THE Pro Script Builder SHALL send the Story_Blueprint and Story_Intent to the LLM and request a full script draft.
3. WHEN the LLM returns a script draft, THE Pro Script Builder SHALL parse the draft into Scene_Heading, Action_Line, Dialogue_Block, and Parenthetical fields and populate the script.
4. WHEN the AI-generated script is populated, THE Pro Script Builder SHALL display a message: "AI-generated draft loaded. Edit and refine as needed."
5. WHEN the user edits an AI-generated field, THE field SHALL be marked as user-edited (optional visual indicator).
6. THE AI-generated mode SHALL be optional — users must explicitly choose to generate with AI.
7. IF the LLM fails to generate a script, THE Pro Script Builder SHALL display an error message and allow the user to retry or switch to user-written mode.
8. THE AI-generated mode SHALL NOT auto-execute — the user must explicitly confirm before the draft is loaded into the script.

### Requirement 14: Export & Conversion - PDF and TXT Export

**User Story:** As a screenwriter, I want to export my completed script as a PDF or TXT file, so that I can share it with collaborators or submit it to festivals and studios.

#### Acceptance Criteria

1. WHEN the user clicks "Export" in the Pro Script Builder, THE Pro Script Builder SHALL display export options: PDF and TXT.
2. WHEN the user selects PDF export, THE Pro Script Builder SHALL generate a PDF file with proper screenplay formatting, page breaks, and a title page (if provided).
3. WHEN the user selects TXT export, THE Pro Script Builder SHALL generate a plain text file with screenplay formatting preserved (Scene_Heading in all caps, Action_Line left-aligned, Dialogue centered, etc.).
4. WHEN the user exports, THE exported file SHALL be named with the project name and export format (e.g., "my-story.pdf", "my-story.txt").
5. THE exported PDF SHALL include: title page (project name, author, date), page numbers, proper screenplay formatting, and a table of contents if the script exceeds 10 pages.
6. THE exported TXT file SHALL preserve all screenplay formatting using text-based conventions (e.g., all-caps Scene_Heading, centered Dialogue).
7. WHEN the user exports, THE Pro Script Builder SHALL NOT modify the original script — the export SHALL be a separate file.
8. THE export feature SHALL support exporting the entire script or a selected range of scenes.

### Requirement 15: Export & Conversion - Optional Prompt Conversion

**User Story:** As a filmmaker, I want to optionally convert my completed script into shot-by-shot prompts for the Director Brain, so that I can use the script to generate visual shot lists and storyboards.

#### Acceptance Criteria

1. WHEN the user clicks "Convert to Prompts" in the Pro Script Builder, THE Pro Script Builder SHALL display a confirmation dialog: "This will convert your script into shot-by-shot prompts for the Director Brain."
2. WHEN the user confirms, THE Pro Script Builder SHALL parse the script into individual scenes and shots, and generate a prompt for each shot based on the Scene_Heading, Action_Line, and Dialogue.
3. WHEN the prompts are generated, THE Pro Script Builder SHALL open the Director Brain with the prompts pre-loaded, allowing the user to review and refine them.
4. THE generated prompts SHALL include: scene number, shot type (inferred from Action_Line), location, characters, action, and dialogue.
5. WHEN the user converts to prompts, THE original script SHALL remain unchanged — the conversion SHALL create a separate prompt list.
6. THE prompt conversion SHALL be optional — users must explicitly choose to convert.
7. IF the script contains ambiguous or incomplete scene descriptions, THE Pro Script Builder SHALL flag those scenes and ask the user to clarify before generating prompts.
8. WHEN the prompts are loaded in the Director Brain, THE user SHALL be able to edit, add, or delete prompts before proceeding to shot generation.

### Requirement 16: Character Arc Mapping - Optional Deep Feature

**User Story:** As a screenwriter, I want to optionally map character arcs with full detail, so that I can track character transformation and ensure emotional consistency throughout the script.

#### Acceptance Criteria

1. WHEN the user clicks "Character Arcs" in the Pro Script Builder, THE Pro Script Builder SHALL display a Character_Arc interface showing all characters defined in the Story_Blueprint.
2. IN the Character_Arc interface, THE user SHALL be able to define for each character: starting emotional state, key turning points, emotional beats at each scene, and ending emotional state.
3. WHEN the user defines a Character_Arc, THE Pro Script Builder SHALL store the arc data in the Story_Blueprint and display a visual arc diagram showing the character's emotional journey.
4. WHEN the user hovers over a scene in the script, THE Pro Script Builder SHALL display the character's emotional beat at that scene (if defined).
5. THE Character_Arc feature SHALL be optional — users must explicitly choose to map character arcs.
6. WHEN the user maps a character arc, THE Director Brain SHALL be able to access the arc data and provide feedback on character consistency and emotional authenticity.
7. IF the user does not map character arcs, THE Pro Script Builder SHALL NOT require it — the script can be completed without arc mapping.
8. WHEN the user exports the script, THE Character_Arc data SHALL be stored separately (not in the exported PDF/TXT) but remain accessible in the project.

### Requirement 17: Pro Mode Integration - Alongside Existing Story Engine

**User Story:** As a filmmaker, I want Pro Mode to be a separate entry point from the existing Story Engine, so that I can choose between prompt-writing and professional scriptwriting based on my workflow.

#### Acceptance Criteria

1. WHEN the user opens MOKHA FILM Suite, THE main interface SHALL display two entry points: "Story Engine" (existing prompt-writing tool) and "Pro Mode" (new scriptwriting tool).
2. WHEN the user clicks "Pro Mode", THE Pro Mode interface SHALL open with the Configuration_Wizard as the first step.
3. WHEN the user clicks "Story Engine", THE existing Story Engine interface SHALL open unchanged.
4. THE Pro Mode entry point SHALL be visually distinct from the Story Engine entry point (e.g., different icon, label, or color).
5. WHEN the user is in Pro Mode, THE user SHALL NOT see Story Engine features, and vice versa.
6. WHEN the user switches between Pro Mode and Story Engine, THE user's previous work in each mode SHALL be preserved.
7. THE Pro Mode SHALL NOT replace or modify the existing Story Engine — both modes SHALL coexist independently.
8. WHEN the user exports a script from Pro Mode, THE export SHALL NOT interfere with Story Engine projects.

### Requirement 18: Integration with Director Brain

**User Story:** As a filmmaker, I want the Director Brain to analyze my script and provide cinematic feedback, so that I can improve the script's visual storytelling and structure.

#### Acceptance Criteria

1. WHEN the user clicks "Director Brain" in the Pro Script Builder, THE Director Brain panel SHALL open with the current script pre-loaded.
2. WHEN the Director Brain analyzes the script, THE Director Brain SHALL provide feedback on: pacing, structure, character arcs, visual storytelling, and alignment with the Story_Intent.
3. WHEN the Director Brain provides feedback, THE Director Brain SHALL reference specific scenes and shots in the script.
4. WHEN the Director Brain proposes changes (e.g., "Add an establishing shot before Scene 3"), THE Director Brain SHALL render Action_Cards that the user can confirm to apply changes directly to the script.
5. WHEN the user confirms a Director Brain action, THE Pro Script Builder SHALL update the script accordingly.
6. THE Director Brain SHALL have access to the Story_Blueprint and Character_Arc data to provide context-aware feedback.
7. WHEN the user exports the script, THE Director Brain feedback history SHALL be preserved in the project but NOT included in the exported PDF/TXT.
8. THE Director Brain integration SHALL be optional — users can write scripts without using the Director Brain.

### Requirement 19: Integration with Shot Critique

**User Story:** As a filmmaker, I want to use Shot Critique to analyze individual shots described in my script, so that I can refine the visual composition and cinematography of each shot.

#### Acceptance Criteria

1. WHEN the user selects a shot description in the Pro Script Builder, THE user SHALL be able to click "Critique Shot" to send that shot to the Shot Critique feature.
2. WHEN the shot is sent to Shot Critique, THE Shot Critique interface SHALL open with the shot description pre-loaded.
3. WHEN Shot Critique analyzes the shot, THE Shot Critique SHALL provide feedback on: composition, lighting, lens choice, camera movement, and visual impact.
4. WHEN the user refines the shot in Shot Critique, THE user SHALL be able to update the shot description in the Pro Script Builder.
5. THE Shot Critique integration SHALL be optional — users can write scripts without using Shot Critique.
6. WHEN the user exports the script, THE Shot Critique feedback SHALL NOT be included in the exported PDF/TXT but SHALL remain accessible in the project.

### Requirement 20: Integration with Agentic Mode

**User Story:** As a filmmaker, I want the Director Brain's Agentic Mode to propose and execute script changes, so that I can quickly iterate on the script with AI-assisted suggestions.

#### Acceptance Criteria

1. WHEN the Director Brain is in Agentic Mode, THE Director Brain SHALL analyze the script and propose specific, executable changes as Action_Cards.
2. WHEN the Director Brain proposes a change (e.g., "Add a reaction shot after Scene 2, Shot 3"), THE Action_Card SHALL include a Confirm button.
3. WHEN the user clicks Confirm, THE Pro Script Builder SHALL apply the change immediately and update the script.
4. WHEN the user clicks Reject, THE Action_Card SHALL be marked rejected and no change SHALL be made.
5. THE Agentic Mode integration SHALL follow the same Confirm_Model as the existing Director Brain Agentic Mode (no silent auto-execution).
6. WHEN the user confirms an action, THE change SHALL be pushed onto the Undo_Stack so the user can undo it with Cmd+Z / Ctrl+Z.
7. THE Agentic Mode integration SHALL be optional — users can use the Director Brain in diagnostic mode without Agentic Mode.
8. WHEN the user exports the script, THE Agentic Mode action history SHALL be preserved in the project but NOT included in the exported PDF/TXT.
